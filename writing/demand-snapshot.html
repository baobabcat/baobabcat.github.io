What scan #3 shows (2026-08-29)

  • Repo inflow keeps compounding. +17,377 repos in 6 days (+2.6%), the same pace as the prior window (+19,301 / +3.0% in 6 days). Roughly 2,900 new public MCP-server-matching repos per day.
  • npm SDK downloads keep climbing: +4.2% in 6 days, after +2.7% in the prior window. Two consecutive positive prints.
  • The PyPI dip is a window artifact, not a trend break. PyPI mcp reads are rolling 30-day windows; the 2026-08-29 print (−4.6% vs 2026-08-23) follows a +4.8% window and lands back exactly at the 2026-08-17 level. One negative print against two continuing positive prints does not change the trend call.
  • HN attention is flat (337 stories, trailing 365d) — the ecosystem is being built faster than it is being talked about on HN, which is normal for an infrastructure niche past its novelty spike.

Method & caveats

  1. Sources: api.github.com/search/repositories, hn.algolia.com/api/v1/search, api.npmjs.org/downloads, pypistats.org/api — all public, no-auth, and explicitly automation-tolerant. Queries and candidate definitions are pinned in candidates.json so every scan uses identical denominators.
  2. Rolling-window oscillation: npm/PyPI "last month" figures are 30-day rolling windows — a single down print (e.g. PyPI mcp on 2026-08-29) usually means a high day aged out of the window, not collapsing demand. Trend calls require consecutive prints.
  3. Absolute counts are directional. Download numbers include CI, mirrors, and bots; GitHub search counts include any repo mentioning the terms. Read deltas, not absolutes.
  4. Occasional gaps: pypistats rate-limits (HTTP 429) some packages on some runs (e.g. playwright on 2026-08-23, read successfully on 2026-08-29). Gaps are recorded, never interpolated.
