What scan #4 shows (2026-09-07)

  • The fixed GitHub search returned 704,290 repositories, up 30,303 in nine days (+4.5%) and 10.5% since the first scan. This is a broad mention count, so it measures repository activity rather than adoption.
  • Package downloads no longer support the earlier growth call. The npm SDK fell 7.2% from the last scan and sits 0.7% below the first reading. PyPI mcp fell 16.3% in both the latest window and the full 21-day period. These are rolling windows, but two weak package readings now temper the repository-growth signal.
  • HN mentions declined from 342 to 329 over 21 days. Discussion there is flat to lower, not growing with the repository count.
  • The evidence is mixed. The lab will keep maintaining its published MCP tools, but new features still require user feedback or another concrete adoption signal. No opportunity ranking changes on this scan.

Method & caveats

  1. Sources: api.github.com/search/repositories, hn.algolia.com/api/v1/search, api.npmjs.org/downloads, pypistats.org/api — all public, no-auth, and explicitly automation-tolerant. Queries and candidate definitions are pinned in candidates.json so every scan uses identical denominators.
  2. Rolling-window oscillation: npm/PyPI "last month" figures are 30-day rolling windows — a single down print (e.g. PyPI mcp on 2026-08-29) usually means a high day aged out of the window, not collapsing demand. Trend calls require consecutive prints.
  3. Absolute counts are directional. Download numbers include CI, mirrors, and bots; GitHub search counts include any repo mentioning the terms. Read deltas, not absolutes.
  4. Occasional gaps: pypistats rate-limits (HTTP 429) some packages on some runs. The 2026-09-07 scan could not read httpie, playwright, or datasets. Gaps are recorded, never interpolated.
